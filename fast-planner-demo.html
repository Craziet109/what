01 为什么需要“前端”这一步？

P2 · P3 · P5

Fast-Planner 能在未知森林、室内杂乱房间、室外树林里做高速自主飞行： 讲稿里的实测条件是速度上限 2.5 m/s、加速度上限 1.5 m/s²，视频没有加速播放。 这意味着规划器必须在毫秒级给出结果，而且给出的轨迹要真的能被控制器跟踪。

传统 A* 只回答一个问题：“栅格地图上哪条路最短？” 它不知道四旋翼有惯性、加速度有上限、转弯要提前减速。 你把它搜出来的折线路径直接丢给控制器，结果就是——要么飞不出来，要么疯狂抖动。

所以 Fast-Planner 把规划拆成两段职责：

  • 前端（Front-End）：用 Hybrid A* 在满足运动动力学约束的连续状态空间里搜一条粗糙但可行的初始轨迹。要快，不要求最优。
  • 后端（Back-End）：把这条初始轨迹当作初值，做梯度下降式轨迹优化 + 迭代时间调整，把它磨成平滑、动力学更优的轨迹。
一句话结论 前端的产出 = 一条无碰撞、满足动力学约束的初始轨迹。
它不是最终答案，它是后端的起点。前端搜得越快越“靠谱”，后端就越不容易陷进坏解。

讲稿 P3 视频画面上的文字（实验条件）

  • Aggressive autonomous flight in an unknown forest —— 未知森林中的激进自主飞行
  • Indoor Flight: Scene 1, Trial 1, Play Speed 1X —— 室内试飞，视频未加速
  • Outdoor Flight: Forest 1, Trial 1, Play Speed 1X —— 室外森林试飞，视频未加速
  • Trajectory and map visualization；Red curve: executing trajectory —— 红色曲线是正在执行的轨迹
  • Velocity Limit: 2.5 m/s；Acceleration Limit: 1.5 m/s² —— 速度与加速度上限

这些条件合起来说明一件事：前端要在未知环境里、用接近极限的机动能力实时给出可行轨迹。 所以它追求的是“快而可行”，不是“最优”—— 最优化留给后端。

“折线路径”与“可飞轨迹”的差别

蓝虚线：栅格最短路，拐角处要求速度瞬间反向 —— 物理上做不到。
红线：满足加速度上限的轨迹，拐弯是提前减速画出来的弧。

Fast-Planner 框架流程图（可重放）

注意后端是一个内循环：算代价与梯度 → 梯度下降 → 更新曲线，转几轮之后才做迭代时间调整。 前端只跑一次，却是整条链路的“起跑线”。

两条流水线各自的职责

① Front-End · Hybrid A*

运动动力学路径搜索（Kinodynamic Path Searching）。在连续状态空间里离散地前向扩展，得到一条安全且动力学可行的初始轨迹。

x = [pT, vT]T ∈ R6 ,  u = a ∈ [−umax, umax]3

② Back-End · Trajectory Optimization

把初始轨迹参数化为多项式/样条，反复执行：

  • calculate cost and gradient —— 计算代价与梯度
  • gradient descent —— 梯度下降
  • update curve —— 更新曲线

收敛后再做 Iterative Time Adjustment（迭代时间调整），让轨迹在时间分配上也动力学可行。

记住这个分工 前端决定“走哪条大方向”，后端决定“怎么走得漂亮”。

Algorithm 1: Kinodynamic Path Searching P7

Initialize();
while ¬P.empty() do
  n_c ← P.pop(); C.insert(n_c);
  if ReachGoal(n_c) ∨ AnalyticExpand(n_c) then
    return RetrievePath();
  primitives ← Expand(n_c);
  nodes ← Prune(primitives);
  for n_i in nodes do
    if ¬C.contain(n_i) ∧ CheckFeasible(n_i) then
      g_temp ← n_c.g_c + EdgeCost(n_i);
      if ¬P.contain(n_i) then
        P.add(n_i);
      else if g_temp ≥ n_i.g_c then
        continue;
      n_i.parent ← n_c; n_i.g_c ← g_temp;
      n_i.f_c ← n_i.g_c + Heuristic(n_i);
return RetrievePath();
等待开始…

代码里那几个“新面孔”在干什么

  • Expand(n_c)：从当前状态生成一批运动原语（下一节动手看）。
  • Prune(primitives)：把落到同一个离散栅格里的原语只留最便宜的一条 —— 这是让连续空间搜索不至于爆炸的关键。
  • CheckFeasible(n_i)：动力学可达？不超速？不撞障碍？三者缺一不可。
  • ReachGoal(n_c)：状态已经贴近终点。
  • AnalyticExpand(n_c)：不再一步步扩展，直接解析地尝试连到终点；成功就结束搜索（演示里能看到这一步的“临门一脚”）。
  • Heuristic(n_i)：见第 06 节，它不是欧氏距离。
P 与 C 是什么 P 是 open list（优先队列），C 是 closed set。第 13–14 行说的是：如果这个节点已经在队列里，而且新算出来的代价并不更优，就跳过 —— 和 A* 的松弛操作一个意思。

04 运动原语：Hybrid A* 的“一步”长什么样

P8 · P9 · P10 · P11

前端每扩展一次，就是站在当前状态上，往各个方向“试一脚油门”，各自积分一小段时间。 这一小段轨迹就叫做一个 primitive（运动原语）。

原语发射台

P10 · P11
每轴 5 档 二维原语 25 条 三维原语 125 条

每条彩色曲线 = 一个恒定加速度输入持续 τ = 0.9 s 的结果（与第 03 节搜索演示同一套参数）。颜色越暖代表 ‖u‖ 越大。 这就是第 03 节右侧搜索里“一步”的真身。

把 v0 从 0 拖大：初速度为零时原语是直线；一旦有了初速度， p(t) = p0 + v0t + ½u t² 就画成了抛物线 —— 这正是“状态里必须同时包含位置和速度”的原因：同样的加速度，从不同速度出发会走出不同的曲线。

结论卡片（推导略，结论必记）

① 轨迹被写成多项式

p(t) := [px(t), py(t), pz(t)]T
pμ(t) = Σk=0..K ak tk,   μ ∈ {x, y, z}

三个轴各自独立地用一个多项式表示。比如 K = 2、μ = x 时就是 px(t) = a0 + a1t + a2t²。

② 四旋翼在这套框架里就是一个线性时不变（LTI）系统

x(t) := [p(t)T, ṗ(t)T, …, p(n−1)(t)T]T ⊂ R3n
u(t) := p(n)(t) ∈ U := [−umax, umax]3 ⊂ R3

状态里装着位置和它的各阶导数（直到 n−1 阶），控制输入就是位置的第 n 阶导数，并且被限制在立方体 [−umax, umax]³ 里。

③ 状态方程：给定初值和控制，未来状态是确定的

x(t) = eAt x(0) + ∫0t eA(t−τ) B u(τ) dτ

这行式子的意义就是：只要知道初始状态 x(0) 和这一段的控制输入 u(τ)，整段轨迹的末状态就算得出来。 所以“试一脚油门 + 积分一次”= 得到一个候选状态节点，这就是原语。

④ 离散化：每轴 2r+1 档，三轴组合出 (2r+1)³ 条原语

{−umax, −(r−1)/r·umax, …, (r−1)/r·umax, umax}  →  每轴 2r+1 个值
组合数 = (2r+1)3

每个轴上的控制量均匀地切成 2r+1 档（含 0），三轴一组合就有 (2r+1)³ 个候选控制输入； 每个候选持续 τ 时间、积分一次状态方程，就长出一条原语。

⑤ Fast-Planner 的具体取值：n = 2

x = [pT, ṗT]T = [px, py, pz, vx, vy, vz]T ∈ R6
u = p(2) = [ax, ay, az]T ∈ R3

状态是位置 + 速度（6 维），控制是加速度（3 维）。 换句话说：一条原语 = 恒定加速度保持 τ 秒，轨迹是二次多项式，在二维平面上就是一条抛物线（左侧演示正是这么画的）。 演示里的速度上限 2.5 m/s 就对应真实实验的限速。

想一想 r 越大，原语越密、轨迹越精细，但每扩展一个节点要算 (2r+1)³ 条轨迹。 r 其实是“搜索精度”和“实时性”之间的那个旋钮 —— 把上面的滑块从 1 拖到 4，看候选数量怎么涨（r=1 → 27 条，r=4 → 729 条，涨了 27 倍）。

05 代价：什么样的“一步”算便宜？

P12

代价拆解器

P12
单条原语 ec = — 不含 ρ：‖u‖²τ = — 5 段总代价 gc = —

拖动加速度：代价按 平方 增长 —— 这解释了为什么搜索天然偏好“温柔”的轨迹。 调大 ρ：相当于给“每一步的时间”额外收费，促使搜索少走步数。

单条原语的代价

ec = ( ‖ud‖² + ρ ) · τ

‖ud‖² 是这条原语所用控制输入的平方范数（加速度越大越贵，而且是平方级地贵）； ρ 是附加惩罚项；再乘上原语的持续时间 τ。直觉上就是：“猛踩油门”要付钱，“磨时间”也要付钱。

一条 J 段轨迹的真实代价

gc = Σj=1..J ( ‖(ud)j‖² + ρ ) · τ

把路径上所有原语的代价加起来，就是这条轨迹从起点走到当前的实际代价 （伪代码里的注释写得很清楚：actual cost of an optimal trajectory from the start state to the current state）。

它在伪代码里的位置 P12 · P14 红框

g_temp ← n_c.g_c + EdgeCost(n_i);
if ¬P.contain(n_i) then P.add(n_i);
else if g_temp ≥ n_i.g_c then continue;
n_i.parent ← n_c;  n_i.g_c ← g_temp;
n_i.f_c ← n_i.g_c + Heuristic(n_i);

g_temp：如果经由当前节点 nc 走到新节点 ni，实际代价会是多少。
更优就更新：把 ni 的父节点改成 nc、gc 改成 g_temp，顺便刷新 fc = gc + Heuristic。
不小于就 continue：这条更差的走法直接丢掉。

一句话结论 搜索在做的其实是最小化这个累加代价；A* 的 f = g + h 在这里变成 fc = gc + Heuristic，其中 h 由下一节的边值问题给出。

06 启发式代价：不用欧氏距离，而是解一个最优控制问题

P13 · P14

如果启发式只是“到终点的直线距离”，它会完全无视动力学：明明需要先减速再转向，它却以为可以直接冲过去。 Fast-Planner 的做法是：求解一个两点边值最优控制问题，把它的最优代价直接当作启发式。

问题设定

给定当前状态 (pμc, νμc) 和目标状态 (pμg, νμg)，在所有能把前者送到后者的轨迹里，找那条使代价 T(T) 最小的。工具是 Pontryagin 最小原理，结果是一个三次多项式：

p(t) = a3t3 + a2t2 + a1t + a0

边界条件：

p(0) = pμc,   ṗ(0) = νμc
p(T) = pμg,   ṗ(T) = νμg

最优轨迹的闭式解（结论必记）

pμ*(t) = (1/6) αμ t3 + (1/2) βμ t2 + νμc t + pμc
[αμ ; βμ] = (1/T3) · [ −12  6T ; 6T  −2T2 ] · [ pμg − pμc − νμcT ; νμg − νμc ]

把 α、β 代回去，得到控制输入（加速度）：

aμ*(t) = αμ t + βμ  ⟹  u(t) = [ax(t), ay(t), az(t)]T

结论：最优加速度随时间线性变化（不是常数）—— 这是这套启发式最值得记住的特征，左侧演示里那条红色直线就是它。

最后一步：在时间上找最优的 T

把 α、β 代进代价函数，得到只关于 T 的函数（记作 J(T)）：

J(T) = ∫0T ‖u(t)‖² dt + ρ·T
  • 求根：∂J(T)/∂T = 0；
  • 在候选根里挑使代价最小、并且轨迹可行的那个，记作 Th；
  • 把 J(Th) 当作启发式值，于是 fc ← gc + Heuristic(ni)。
Heuristic(ni) = J(Th)

注意代价里除了 ∫u²dt，还有一个时间惩罚 ρT —— 它和第 05 节边代价 ec = (‖ud‖²+ρ)τ 用的是同一个 ρ。 少了这一项，“慢慢飞”永远更便宜，代价会随 T 单调递减，最优时间 Th 根本不存在（演示里把 ρ 拖到 0 就能看到这个退化）。

为什么这样做更好 这个启发式本身就是一条满足边界条件的动力学可行轨迹的代价，所以它比欧氏距离“更懂物理”， 搜索时更少被无关方向吸引。
注意 T 太小会无解（短时间内到不了），演示里会直接提示你。

07 把前端串起来：一次 Hybrid A* 到底做了什么

P15
  1. 弹出最便宜的节点 nc ← P.pop()：优先队列里 f = g + h 最小的那个。
  2. 判断到达：ReachGoal(nc) 或 AnalyticExpand(nc) 成功 → RetrievePath() 回溯路径，搜索结束。
  3. 扩展原语 primitives ← Expand(nc)：生成 (2r+1)³ 条候选（Fast-Planner 里是恒定加速度保持 τ）。
  4. 剪枝 nodes ← Prune(primitives)：同一栅格只留最便宜的一条，控制分支数量。
  5. 可行性检查 CheckFeasible：动力学是否可达、是否超速、是否碰到障碍。
  6. 算边代价 g_temp = n_c.g_c + EdgeCost(n_i)，用 (‖u_d‖²+ρ)τ 累加。
  7. 松弛更新：新节点入队；已在队列里且新代价更优就更新父节点、gc，然后刷新 fc = gc + Heuristic(ni)。
  8. 循环回到第 1 步，直到抵达终点或队列为空。
前端交付物 一条满足运动动力学约束、无碰撞的初始轨迹，随后交给后端做轨迹优化与迭代时间调整。

08 小结 · 必记结论清单

全篇

模型

四旋翼 = LTI 系统；状态 x 含位置及其到 n−1 阶导数（3n 维），控制 u = p(n)，限幅 [−umax, umax]³。

Fast-Planner 取值

n = 2：x = [p, v] ∈ R6，u = a ∈ R3。原语 = 恒定加速度持续 τ。

状态方程

x(t) = eAtx(0) + ∫eA(t−τ)Bu(τ)dτ —— 有初值和控制就能推未来状态。

离散化

每轴 2r+1 档 → 共 (2r+1)³ 条原语。r 是精度与实时性的旋钮。

代价

ec = (‖ud‖²+ρ)τ，gc = Σ ec，fc = gc + Heuristic。

启发式

两点边值最优控制的最小代价：三次多项式轨迹，a*(t) = αt + β 线性；∂T*/∂T = 0 得 Th，Heuristic = T*(Th)。

两个关键技巧

Prune 剪枝【同一栅格留最便宜】 + AnalyticExpand 解析扩展【临门一脚直达终点】。

分工

前端一次搜索出初始轨迹；后端反复优化 + 迭代时间调整。前端要快，不要最优。

自测：点开看答案

Q1：为什么 Hybrid A* 每扩展一个节点要算 (2r+1)³ 条轨迹，而不是 8 条？

因为它扩展的不是固定方向的栅格邻居，而是离散化的控制输入：三个轴各 2r+1 档，组合数是 (2r+1)³。每条候选控制输入持续 τ 时间、积分一次状态方程，得到一条运动学可行的曲线 —— 代价是计算量大，收益是轨迹天然符合动力学约束。

Q2：为什么启发式不用欧氏距离？

欧氏距离无视动力学：它假设可以瞬时改变速度方向。Hybrid A* 用的启发式是两点边值最优控制问题的最优代价，它本身就是一条满足边界条件（当前位置/速度 → 目标位置/速度）的可行轨迹的代价，因此更贴近真实剩余代价，指导搜索更有效。

Q3：Prune 这一步行不行？删掉了原语不会漏掉最优解吗？

会牺牲一部分最优性，但换来可接受的计算量。Prune 把落在同一个离散栅格（位置+速度量化后）的原语只保留代价最小的一条，避免大量“几乎一样”的节点同时进入 open list。前端的目标本来就是快速拿到一条可行初始轨迹，精细的最优性由后端优化负责。

Q4：为什么最优加速度 a*(t) = αt + β 会是线性的？

在“最小控制代价 + 固定端点位置与速度”的两点边值问题里，用 Pontryagin 最小原理得到的最优控制是时间的一次函数；位置则是它的二次积分，也就是三次多项式 p(t) = (1/6)αt³ + (1/2)βt² + νct + pc。α、β 由边界条件解出，只与 Δp、Δv 和 T 有关。

Q5：启发式的代价里为什么必须有时间项 ρT？

因为 ∫‖u‖²dt 只惩罚“控制量”：T 越大，连接同样两点所需的加速度越小、这一项越低。如果只有它，代价会随 T 单调递减——“慢慢飞”永远更便宜，∂J/∂T = 0 没有有限根，也就谈不上“最优时间 Th”。加上 ρT 之后“磨时间”也要付费，才出现真正的极小点。这正是边代价 ec = (‖ud‖²+ρ)τ 里那个 ρ 存在的理由 —— 搜索与启发式用的是同一个代价口径。把第 06 节的 ρ 拖到 0，就能看到这个退化。
